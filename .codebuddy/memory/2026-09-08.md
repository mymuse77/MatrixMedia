# 2026-09-08

## 修复 pnpm run dev 启动失败（ERR_PNPM_IGNORED_BUILDS）

- 环境：pnpm v11.22.0。v11 起 `package.json` 的 `pnpm` 字段不再被读取，构建脚本白名单改用 `pnpm-workspace.yaml` 的 `allowBuilds` 映射（`onlyBuiltDependencies` 等已在 v11 移除）。
- 处理：在 `pnpm-workspace.yaml` 中把自动生成的占位值改为 `true`（`@swc/core`、`core-js`、`electron`、`esbuild`、`vue-demi`），并撤销先前误加到 `package.json` 的 `pnpm.onlyBuiltDependencies`。
- 结果：`pnpm install` 正常执行 electron / esbuild / @swc/core / vue-demi 的 postinstall，退出码 0，不再报 `ERR_PNPM_IGNORED_BUILDS`。

## 修复打包后客户端运行报 Cannot find module 'body-parser'

- 排查方法：`npx @electron/asar list build\win-unpacked\resources\app.asar` 导出清单后统计，确认 express 本身在 asar 中，但其全部传递依赖（body-parser、qs、accepts、send、serve-static 等约 30 个）命中数为 0。
- 根因：`.npmrc` 里的 `node-linker=hoisted` 被 pnpm 11 **完全忽略**（v11 起 `.npmrc` 只保留 auth/registry，其余设置必须放 `pnpm-workspace.yaml`），实际安装仍是默认 isolated 模式（`node_modules/.pnpm` 虚拟存储，1241 个包），electron-builder 只把顶层 deps 打进 asar，传递依赖丢失。
- 处理：`node-linker=hoisted` 从 `.npmrc` 移除，改在 `pnpm-workspace.yaml` 写 `nodeLinker: hoisted`。
- 注意：`pnpm config get node-linker` 返回 undefined 可验证配置未被读取；改到 workspace 文件后 `pnpm config get nodeLinker` 返回 `hoisted`。
- 遗留：现有 `node_modules/.pnpm` 仍在，需 `pnpm install --force` 重建为扁平结构后重新打包，否则打包结果不变。
